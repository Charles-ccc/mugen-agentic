# Workflow 和 Agent 的主要权衡点是什么

## 问题

Workflow 和 Agent 的主要权衡点是什么？

## 状态

1. 初稿

## 为什么重要

这道题决定系统设计的起点。

判断失误时，常见后果有三类：

1. 原本适合固定流程的任务被做成高成本、难调试的 Agent。
2. 原本需要运行时决策的任务被压成过度僵硬的 workflow。
3. 后续评估变得混乱，团队很难判断收益到底来自哪里。

## 短答案

Workflow 和 Agent 的核心权衡集中在控制流、可靠性、成本和任务适配性这四个方面。

任务目标清晰、流程稳定、失败代价高时，workflow 更合适。任务路径依赖运行时观察、信息不完整、需要动态调整策略时，Agent 的价值更高。

## 展开说明

可以先按四组维度理解这道题。

1. 控制流与灵活性

Workflow 的执行路径通常是预先定义好的，可以通过代码或图结构进行编排。系统会沿着既定节点推进，控制力强。

Agent 的路径是动态的。系统会根据中间观察决定下一步动作，适合应对突发情况、信息缺口和非预期输入。

2. 确定性与可靠性

Workflow 的节点边界清晰，测试、审计和追踪都更直接。

Agent 的路径会随推理过程变化，结果波动更大，复现和调试成本也更高。幻觉、误调用和循环执行都是常见风险。

3. 成本与耗时

Workflow 的大模型调用次数和 token 消耗通常更可预测，响应速度也更稳定。

Agent 往往要经历多轮推理、工具调用、重试和反思，成本和时延都会上升。

4. 任务复杂度与环境依赖

Workflow 适合结构化、可拆解、重复性强的任务。

Agent 更适合开放式、动态变化、依赖外部环境反馈、需要协调多个工具的任务。

从工程角度看，很多系统的最优解落在中间地带：主流程用 workflow 保持稳定，把最不确定、最依赖运行时判断的局部节点做成 agentic 决策。

## 常见误区

1. 把 workflow 当成低级方案，默认认为 Agent 更先进。
2. 把 Agent 当成默认升级方向，没有先验证任务是否真的需要动态决策。
3. 只在纯 workflow 和纯 Agent 两端做选择，忽略混合结构的价值。
4. 只看功能是否完成，忽略成本、稳定性和调试难度。
